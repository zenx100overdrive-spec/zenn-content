## 放置して稼ぎたかった

10月1日の午後、私は音声入力でこう話していました。

> 放置してても金が稼げるというか、仕組みを作りたい。で、まあアイディアとしては楽天ポイントとかポイント系、楽天ポイントとかを、あの、今だいぶ前から流行ってるAIが自動的に、えっと、アフィリエイトっていうかな、調べたんだけど。アフィリエイトとか。（中略）ただこれこっちに関しては俺はあんまり介入したくないなと思ってて。

同じ話の中で「楽天ルームっていうマーケットがあって」とも言っていたので、Claude Code はこれを「楽天ROOMへの投稿をAIで自動化する」案と読み、規約の原文を取りに行きました。数分後に返ってきたのがこれです。

> 楽天ROOM 利用規約 第11条第1項第4号：「スクリプトその他のプログラムを実行する等の方法により、機械的に投稿、コメント等をする行為」は禁止。
> → 投稿まで自動化する形は規約違反。この形では進めない。

止めたのは**機械的に投稿する部分だけ**です。そのうえで「AIが候補と文を用意して、人が選んで手で投稿する」「自分のサイトに置く」という別の形を並べてきました（手で投稿する形については「第11条第1項第4号の“機械的な投稿”には当たらない」とだけ返し、規約全体で問題ないかまでは断定していません）。私は、自分のサイトは「マーケティングがマーケティングを呼ぶ」状態になるから合わない、と話しただけで、その条件は次の調査に入っていました。

楽をしたくて私が言った案を、AIの側が規約の条文で止めた、という順番でした。

## 70分、声だけだった

10月1日の14:03〜15:13、私は椅子の座席を倒して、音声入力でしゃべっていただけでした。数えると**音声17回**（音声入力の書き起こしファイル1つを1回と数えています）。その間、Claude Code へのキーボード入力・貼り付けは**0回**です（この時間帯にClaude Code へ届いた入力を、作業ログで確認した値）。

## その70分で、Claude Code がやったこと

| やったこと | 中身（数字はその時点の値） |
|---|---|
| 話した事業の考えを企画メモに | 私の言葉だけで構造化（意見は別欄に分けて） |
| 過去の市場分析の集約 | 事業の記録37件のうち、**金額の記録は0件**（＝売上の記録が無い） |
| 規約の確認 | 楽天ROOM 利用規約 第11条第1項第4号（上の引用） |
| noteの棚の大きさを数えた | `#生成AI` のハッシュタグ **577,569件**（この日の時点） |

その後に私がこぼした感想です（書き起こしの誤変換だけ直しています）。

> 俺が音声入力した時点でクロードが勝手に参照してくれてるから、もう市場調査が始まってるんだよ。俺はすごく助かってるよ。

## 仕組み：声に気づく方法

やっていることは3つだけです。

1. ChatGPT/Codex アプリで音声入力すると、書き起こしがPCのローカルに残る。
2. **2分ごと**に、書き起こしを自分用の記録（ローカルのファイル）へ保存するタイマーを動かす（これは下の「事故」のあとで足したもの）。
3. Claude Code のセッションの中で、「新しい書き起こしが出るまで待つ」スクリプトを**バックグラウンドで**動かしておく。20秒ごとに確認して、新しいものが出たら終了する。終了すると Claude Code に通知が来るので、そこで起きて本文を読む。

```python
# 新しい書き起こしが出るまで待つ（本文は出力しない）
while time.time() < end:
    new = {k: v for k, v in completed().items() if k not in seen}
    if new:
        print(json.dumps({"event": "NEW_VOICE", "count": len(new)}))
        break
    time.sleep(20)
```

送信ボタンも、整形も、貼り付けも要りません。Claude Code のセッションを開いたままにしておくのが前提です。

## 事故：書き起こしが20件しか残らなかった

この日、途中で分かったことがあります。音声入力アプリの履歴は**新しい20件しか残らない**ので、私が話し続けると古い書き起こしから消えていきます。気づいたときには、午後の5件がPCから消えていました。

- 消えた5件は、Claude Code が自分の作業ログ（読んだときに出力していた本文）から取り戻しました。
- それ以後は、上の「2分ごとの保存」で全部を残しています。

音声入力をエージェントにつなぐなら、**元の履歴が消える前に自分の側へ写す**仕組みが先に要る、というのがこの日の学びです。

## それでも、人に残ったこと

この日、私のところに戻ってきたのは次の4つでした。

1. **公開するかどうか**。Claude Code は下書きまで作り、「公開は人の判断」として止まりました。私は「公開してよし」と返しただけです。
2. **ログインが要る操作**。Zenn のアカウント連携と GitHub のリポジトリ作成は、私の認証が必要なので、手でやりました。
3. **事実の確認**。タイトル案の「寝ながら」は、記録に残っていたのが「寝ながら動画を見ていた」だけだったので、Claude Code が確認を返してきました。私が「基本俺は椅子座席倒してゆっくりしてる」と答えて決まりました。人に聞かずに決めていたら、事実と違うタイトルになっていたところです。
4. **どこまで消すか**。古い記事の扱いは「削除処理はgithubの方だけで大丈夫」の一言で決まりました。

数字の誤りも、公開前の見直しで1つ直っています（最初の下書きは「音声11回」、正しくは17回）。

## 前と比べて

8月末〜9月中旬のChatGPTとの会話を数えると、まとまった相談（30分以内に続いた一続きのやり取り）49回のうち34回で、AIに「依頼書」を書かせていました。AIの出力を別のAIに貼り付けた回数は約150回です（AIの報告文の形をした入力を機械的に数えた値）。

この日の70分は、それが**0回**でした。ただし1日分の記録なので、毎日そうなるとはまだ言えません。

## 限界

- 書き起こしは手元のPCに保存していますが、**Claude Code が読むときは、その本文がモデルの提供元に送られます**。AIに向けていない独り言や個人的な話も、待機中なら読まれます。
- Claude Code 宛てと分かる話以外は、指示ではなく「考えの記録」として扱う、と決めています（この日のテスト音声「テストテスト」には、受け取ったことを返しただけでした）。
- アプリでの会話の本文そのものはPCに残らないので、拾えるのは音声の書き起こしだけです。
