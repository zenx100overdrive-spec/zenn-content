## 何が起きたか

9月30日の夜、私は Claude Code に「人の仕事を減らす」仕組みをいくつか作らせていました（20分ごとに記録を更新するタイマー、作業ログの集計、私の判断待ちを1ページにまとめる画面など）。

その途中で Claude Code は、自分が書いたコードを **Codex に独立してレビューさせる** と決めて、勝手に依頼を出しました。私はその間、別の指示（API の予算や Codex の使い方の話）を送っていただけで、レビューには一切触っていません。

## 依頼の仕方

Claude Code が Codex に渡した依頼は、短い Markdown 1枚でした。ポイントは3つです。

- **読み取り専用**で動かす（`codex exec -s read-only`）。ファイルは変えさせない。
- 見てほしい観点を絞る：「落ちる・数え間違える・二重に取り込む・データを失う・秘密情報が漏れる・タイマーの多重起動」。
- 答えの形を固定する：`FINDING <番号>: <ファイル>:<行> — <欠陥> — <壊れる具体的な入力> — <重大度>`、最後に `VERDICT: 動かし続けてよい / 次の実行前に直せ`。

## 結果：13個のダメ出し

6分ほどで、13個の指摘と「**次の実行前に直せ**」という判定が返ってきました。

- 重大（HIGH）5件：秘密情報の伏せ漏れが3件、壊れた1行で「判断待ち」が0件に見えてしまう問題、同時に2回動くと同じ記録が二重に入る問題
- 中（MEDIUM）6件：「はい、確認してください」が承認扱いになって依頼の件数から消える、など
- 軽（LOW）2件：キャッシュの扱い

## Claude Code がやったこと

1. 13件を1件ずつ確認して、**12件を修正**。1件は「すでに作業依頼だけを数えている」とコードで確かめて、**修正不要**と判断。
2. 修正をコミットしたあと、**同じ Codex にもう一度「直ったか確認して」と依頼**。
3. 返ってきたのは「10件は直った、3件は直っていない、新しい問題が2件」。
4. その5件も直して、もう一度コミット。

最初の依頼（23:30）から最後の修正のコミット（23:48）まで、およそ20分でした。

## 僕がやったこと

何もしていません。正確には、このループに **一度も触っていません**。コピペも、AI 間の運搬も、「これ直して」の一言もありません。

以前の私は、AI の出力を別の AI に貼り付けてレビューさせるのを自分の手でやっていました。8月末〜9月中旬の会話ログを数えると、それが約150回ありました。

## わかったこと（事実だけ）

- 1回目のレビューで「直した」と言っていた13件のうち、**3件は2回目の確認で直っていなかった**。直したかどうかを、直した本人（Claude Code）ではなく、別の AI に確認させたことで見つかった。
- 「完了」と「検証済み」は別物。これは以前、テストが1117件通っていたのに実モデルの応答が0件だったときに、私が自分のルールにしたことでもあります。

## 限界

- Codex の指摘がすべて正しいとは限りません。1件は Claude Code が確かめたうえで「修正不要」としています。
- Codex は ChatGPT のプラン内で動かしていて、API の従量課金は使っていません（そうなるなら止める、というルールにしています）。
